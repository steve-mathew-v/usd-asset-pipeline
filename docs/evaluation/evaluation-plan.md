# Evaluation Plan — USD Asset Pipeline

*Researcher-facing document. Summarises how the user study is run and analysed.*

## Aim

Assess whether the USD asset pipeline provides usable, reliable, versioned
asset exchange for small teams, and whether it improves on a manual
file-sharing workflow in usability and error reduction.

## Research questions the study answers

1. Can artists complete core pipeline tasks (publish, approve, import, pick a
   version) successfully and quickly, with little help?
2. How usable is the tool, measured by the System Usability Scale (SUS)?
3. Do artists judge it better than their current manual file-sharing method,
   and why?

## Participants

- **Target:** 6–10 artists / TDs (e.g. from the NCCA cohort). 5+ is enough to
  surface most usability issues; 8–10 gives a more stable SUS score.
- **Inclusion:** some Maya (or Houdini) experience; no prior use of this tool.
- Recruit by email / course channels. Participation is voluntary and anonymous.

## Design

- **Type:** task-based usability study with a post-study SUS and short
  comparative questions. Within-subjects (everyone uses the tool).
- **Optional stronger design:** a controlled A/B where each participant also
  performs the *same* share-and-consume scenario manually (cloud drive +
  naming), counterbalancing order, so tool vs manual can be compared directly.
  Note this in the write-up as the more rigorous variant.

## Procedure (about 25–30 minutes per participant)

1. Give the **Participant Information & Consent** form; get signed consent.
2. **Background questionnaire** (2 min).
3. Brief demo of the shelf (2–3 min), then hand over the **Task Sheet**.
4. Participant works through the tasks while the observer records completion,
   time, and any help given (think-aloud encouraged).
5. **SUS questionnaire** (2 min).
6. **Post-study questionnaire** — comparison and open feedback (5 min).

## Measures

| Measure | Source | Type |
|---|---|---|
| Task success (success / partial / fail) | Observer sheet | Effectiveness |
| Time on task | Observer sheet (stopwatch) | Efficiency |
| Errors / assists per task | Observer sheet | Errors |
| Usability score (0–100) | SUS | Perceived usability |
| Tool vs manual rating + comments | Post-study | Comparison |

## Analysis

- **SUS:** score each response (see the SUS sheet), report the mean and range;
  compare against the well-known benchmark (≈68 = average, 80+ = excellent).
- **Tasks:** report success rate per task, mean time, and total errors/assists.
- **Qualitative:** group open comments into themes (what worked, pain points,
  requested features). Pick representative quotes.
- If the controlled A/B is run: compare mean time and error counts, tool vs
  manual.

## Ethics & data

- Voluntary; participants may stop at any time.
- Responses are **anonymous** (use participant IDs P1, P2, …; no names on data).
- Store data securely; report only aggregates and anonymised quotes.
- **Confirm this against Bournemouth University's research-ethics process**
  before running — a taught project involving human participants normally needs
  an ethics checklist/approval.
